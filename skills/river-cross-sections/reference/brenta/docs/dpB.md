# dpB.py

Second pass (2026-11-17), first script. Re-places the **B** reach (Brenta downstream of Borgo) on the candidates of the main reach (`cands.pkl`) with dynamic programming, respecting the constraints at the Bordignon bridge and the 5 m rule. For the B reach only, it replaces the work of `dp.py`. Previous: `place.py`/`dp.py`; next: `export_B.py`.

## Requirements

* Interpreter: Anaconda `python3` (numpy, scipy `cKDTree`, shapely via `core.py`).
* Imported module: `core.py` from `WD/work` (provides `SP` = `sys.argv[1]`, `pickle`, `np`).
* The script must be copied into `WD/work` (where `core.py`, `cands.pkl`, `dp.pkl` are also located).

## Input

* `WD/work/cands.pkl` (`place.py`): candidates; uses the key `main` with `ss` (chainage on the main reach, step 0.25 m), `P` (centerpoint), `n` (normal), `tL`, `tR` (toe distances), `ok`, `pen5`, `hitO`, `hitB`.
* `WD/work/dp.pkl` (`dp.py`): indices chosen on 2026-11-09 for `main` and `vecchio`.
* `WD/xn_points.json` (in the root of `WD`, not in `work/`): list of points `[x, y]` where a non-section nodestring meets a breakline. **No script in the pipeline produces it**: it was prepared separately.

## Output

* `WD/work/dpB.pkl`: dictionary with `N` (indices of the main reach kept, those with `s <= 16130.5`), `B` (new indices of the B reach), `V` (first 60 indices of the Brenta vecchio from `dp.pkl`).
* Print: number, first and last chainage of B, cost; range of the steps and chords; any chords outside 49.5–50.5 m; number of `hitB`/`hitO`, sum of `pen5`, number of candidates with penalty ≥ 1e9.

## Parameters and constants

* `S_BRIDGE = 16327.97` m: (old) chainage of `Ponte_Bordignon_monte`.
* `MARGIN = 5.0` m: B00050 must be at least 5 m upstream of the bridge; the candidates in `(S_BRIDGE − MARGIN, S_BRIDGE + 20)` are forbidden (penalty 1e9).
* `S0MIN = 16266.0`, `S0MAX = 16285.0` m: window in which the first section (B00000) falls on the old chainage. The last run used `S0MIN=16266`.
* Penalties: `pen5` + 1000·`hitO` + 10000·`hitB`; candidates not `ok`: 1e9; +50 for each side whose crossing with the toe falls less than 5 m from a point of `xn_points.json`.
* Admitted steps: `d ∈ {198..202}` cells of 0.25 m (49.5–50.5 m of chainage); step cost `0.01·(d·0.25 − 50)²`; chord outside 49.5–50.5 m: +500 + 100·|chord − 50|.
* End: last section at 5–50.5 m before the end of the chainage (`L = ss[-1] + 0.25`).
* `16130.5` m: upper limit of the indices `N` kept.

## Usage

Working folder layout (`WD`, e.g. `.../v2`): `WD/in` (copies of the six `layers/*_50m.gpkg`), `WD/in0` (copies of the originals `breaklines.gpkg`, `boundary.gpkg`, `regioni_ponti.gpkg`), `WD/work` (`core.py`, `next_bed.py`, `bank.py` and `cands.pkl`, `newfaces.pkl`, `dp.pkl`, `cltab.pkl` from the 2026-11-09 work), `WD/s16130/work` (run of `bank.py` for the extension of S16130), `WD/xn_points.json`.

```bash
cp scripts/dpB.py /path/to/WD/work/
```

```bash
python3 /path/to/WD/work/dpB.py /path/to/WD
```

## How it works

1. Loads the candidates `main` and builds the penalty vector `pen` (see above); the toe points of each candidate (`P ± n·t`) are compared with the points of `xn_points.json` through a KD-tree.
2. Sets to 1e9 the candidates in the bridge zone.
3. Forward dynamic programming: `cost` starts from `pen` for the candidates with `ss ∈ [S0MIN, S0MAX]`; from each candidate `i` with cost < 1e9 it moves to `j = i + d`, updating cost and predecessor.
4. Chooses the end of minimum cost in the window `[L − 50.5, L − 5]`, walks back the predecessors and prints the checks.
5. Saves `N` (indices of `dp.pkl['main']` with `ss <= 16130.5`), `B` and `V`.

## Checks and limits

* Check in the print: all chords in 49.5–50.5 m (empty list), `hitB`/`hitO` = 0, `pen>=1e9` = 0.
* `xn_points.json` is not generated by any script: it must be supplied (if missing, the script stops with `FileNotFoundError`).
* The constants are in the code; the index `S0MIN` was chosen by hand (16266).
* It overwrites `dpB.pkl` on every run.
